## 修掉侧边栏左侧空位（fumadocs 布局）
- **现象**：超宽屏下 docs 侧边栏展开后离视口左边缘空出一段（TOC 右侧同理）。
- **根因**：fumadocs base-ui 的 docs 布局是 5 列 grid，定义在
  `node_modules/.pnpm/@fumadocs+base-ui@*/node_modules/@fumadocs/base-ui/dist/layouts/docs/slots/container.js`：
  `minmax(min-content,1fr) | var(--fd-sidebar-col) | minmax(0, calc(var(--fd-layout-width,97rem) - sidebar - toc)) | var(--fd-toc-width) | minmax(min-content,1fr)`，
  而 `--fd-layout-width: 1400px`（同包 `dist/style.css`）。视口 >1400px 时多出的宽度被左右两个 1fr 空列平分 → 侧边栏被推离左边。
  （默认 `--fd-sidebar-width: 268px`、`--fd-toc-width: 268px`，均定义在 layout 的 Tailwind arbitrary property 里。）
- **修复**：`src/app/global.css` 加 `:root { --fd-layout-width: 100%; }`。空白列归零，sidebar 贴左、TOC 贴右；<1400px 时行为不变。
  正文安全：`dist/layouts/docs/page/slots/container.js` 里 article 有 `max-w-[900px]`（`full` 时 1168px）且外层 `justify-items-center`，放开总宽不会拉长正文行宽。

  - Next 16 dev 有单实例限制，同一目录再起会报 `Another next dev server is already running`，所以验证要用用户已跑着的 3000 端口，不要另起。

## 视频处理（4K → 可用的网页背景）
- 原始：3840x2160 / 60fps / 10s / 31.37MB / 无音轨（H.264）。
- 压缩：`ffmpeg -an -vf "scale=1920:-2,fps=30" -c:v libx264 -crf 30 -preset slow -pix_fmt yuv420p -movflags +faststart`
  → 1920x1080 / 30fps / **2.01MB（15.6x）**，6 秒编完；poster 由 `-ss 1 -frames:v 1 -q:v 4` 生成（191KB）。
- 产物：`public/hero.mp4`（2.01MB，可安全提交）、`public/hero-poster.jpg`。
- **重要技巧**：本机没有 ffmpeg，`npm i ffmpeg-static` 走 GitHub 下载极慢（20 分钟未完成，最终未用）。
  改用 npmmirror 镜像直接取二进制，几十秒完成：
  `curl -L -o ffmpeg.gz https://registry.npmmirror.com/-/binary/ffmpeg-static/b6.0/ffmpeg-win32-x64.gz`
  再用 `zlib.gunzipSync` 解压成 `ffmpeg.exe`（27.6MB 压缩包 → 77.4MB exe，含 libx264/x265/vpx）。ffprobe 同目录同名规律。
- **视觉验证技巧**：`chrome --headless=new --hide-scrollbars --window-size=1440,900 --blink-settings=preferredColorScheme=1 --virtual-time-budget=15000 --user-data-dir=<tmp> --screenshot=<tmp>/x.png <url>`；
  不加 `--blink-settings` 会按系统深色偏好渲染（会误判首页配色有问题）。
- 验证结果：`biome check` / `next typegen`+`tsc --noEmit` / `next build` 全部 exit 0，三个分类路由均正常生成。

## 「主题切换看起来失效」的真实原因与修复（重要，易复发）
- **现象**：用户点导航上的主题切换没反应。实测按钮能点、`<html>` class 确实从 dark→light、
  body 背景 rgb(18,18,18)→rgb(245,245,245)，localStorage 也写入了 —— **切换机制本身一直是好的**。
- **根因**：首页是「整屏视频 + 白字 + 透明导航」，深浅色下渲染结果**逐像素完全一致**
  （实测两张截图 md5 相同）。用户点了但画面毫无变化，就判断为"切换不了"。
- **修复**：`page.tsx` 加 `<div className="rn-hero-shade … bg-black" />` 盖在视频上，
  `global.css` 里 `.rn-hero-shade{opacity:0}`、`html.dark .rn-hero-shade{opacity:0.45}` + 0.4s 过渡，
  再配合底部状态条直接写出"深色模式/浅色模式"文字。修复后两张截图 md5 不同，差异肉眼明显。
- **教训**：这类"某功能失效"的反馈要先分清「机制没生效」还是「生效了但用户看不见」，
  用 CDP 读运行时状态 + 截图 md5 对比，比肉眼看截图靠谱得多。
- CDP 验证套路（比 `--screenshot` 强得多，能读真实计算样式和模拟点击）：
  起 `chrome --headless=new --remote-debugging-port=9224 --user-data-dir=<tmp>`，
  用 `Target.createTarget`+`Target.attachToTarget` 拿 sessionId，再 `Runtime.evaluate` /

## 主题切换选中态：让它"看得出来"（重做）
- **现象**：用户反馈"能切换但看不出来"。截图确认：导航里太阳和月亮一模一样。
- **根因（两条规则叠加）**：fumadocs 的选中态只是给其中一个图标垫一层很淡的 `bg-fd-accent`
  （见 `@fumadocs/base-ui/dist/layouts/shared/slots/theme-switch.js`，light-dark 模式下是两个平级 `<svg>`，靠 active 类区分）。
  而本站的 `.rn-nav-over-hero #nd-nav [class*="text-fd-"] { color:#fff }` 把两个图标**一起刷白**，
  旧的 `.rn-nav-over-hero #nd-nav [data-theme-toggle] svg { background-color: transparent }`
  又把那块圆底**一起清掉** → 视觉上完全等价。
- **修法**：不再依赖 fumadocs 的 active 类，改为直接读 `<html>` 的 dark 类：
  未选中压暗，选中贴圆底。选择器用 `html:not(.dark) …:first-of-type` / `html.dark …:last-of-type`
  （浅色模式第 1 个 `<svg>` 是太阳、深色模式最后一个是月亮，位置固定）。
  - 普通导航（含 docs 侧边栏）：`background-color: color-mix(in oklab, currentColor 16%, transparent)`，
    一条规则自动适配深浅色。
  - 首页透明导航：选中项改「实心白圆 + 深色图标」`#fff` / `#10151c`，视频上对比度最高。
- **踩到的两个坑**：
  1. **选择器不能限定容器**：切换器在首页导航栏里是 `#nd-nav`，在 docs 布局里却在**左侧边栏底部** `#nd-sidebar`
     （`#nd-nav` 里根本没有），只写 `#nd-nav` 会导致文档页完全不生效。
  2. **hero 规则必须带 id**：`.rn-nav-over-hero #nd-nav [class*="text-fd-"]` 优先级 (1,2,0)，
     去掉 `#nd-nav` 后自己的规则 (0,4,1) 压不过它 → 变成「白圆 + 白图标」，圆里什么都看不见（截图实锤）。
     教训：同一个选择器带不带 id 是质变，不是量变。
- **底部状态条**：按用户要求去掉「深色/浅色模式」按钮（`hero-status-bar.tsx` 精简为纯计时器，
  顺带删掉 SunIcon/MoonIcon/MutationObserver/toggleTheme）。

## CDP 验证方法学（本轮新增的两条重要教训）
- **dev server 会骗人**：HMR websocket 握手失败（`ERR_INVALID_HTTP_RESPONSE`）时，SSR HTML 正常返回、
  React 也加载了，但**页面根本没 hydrate** —— 表现为点击无反应、`useEffect` 不跑（页面上的实时时钟永远停在
  `已运行 — 天 --:--:--`）、切换器的 active 类不出现。一开始据此误判成"库的 active 类没应用"，走了弯路。
  可靠的 hydration 判据：`[...document.querySelectorAll('*')].some(el => Object.keys(el).some(k => k.startsWith('__reactFiber$')))`，
  或直接看页面上的实时时钟有没有在跳。**碰到这种情况先重启 dev server 再下结论。**
- **CSS transition 会让 `getComputedStyle` 读到过渡起始值**：改完类名立刻读，拿到的是上一个状态的值，
  会得出"四种状态全反了"的荒谬结论。**改完类名要等 ~700ms 再读/截图**。
- 结论性验证一律走生产模式：`next build` → `next start -p 3100` → CDP 真实鼠标点击 → 计算样式 + 截图。
  本轮据此确认：首页 hero 深/浅两种模式下选中态正确、点击来回切换正确；docs 侧边栏同样正确。

## Vercel 构建失败：ERR_INVALID_URL（线上挂、本地过）
- 现象：Vercel Deployment 报 `Command "pnpm run build" exited with 1`，耗时 26s，日志需展开才可见。
- 逐个排除（都不是原因，但方法值得留）：
  - **锁文件没漂移**：逐条比对 `pnpm-lock.yaml` 里 `importers['.']` 的 specifier 与 package.json，完全一致。
    坑：scoped 包在锁文件里是**带引号的 key**（`'@biomejs/biome':`），按字符串直比会误报一堆「只在 lockfile / 只在 package.json」。
  - **无未声明导入**：npm 的扁平 node_modules 允许导入未声明的包，pnpm 不允许，所以「本地过、线上挂」首先要查这层。
    扫描 src/ content/ scripts/ 全部 import 后确认都已在 package.json 中。
  - 本地 `node_modules/.pnpm` 存在 → 本地本来就是 pnpm 装的，不是 pnpm 严格性问题。
- **真凶**：`src/app/layout.tsx:15` 的 `metadataBase: new URL(siteUrl)` 在**模块加载期**求值。
  `NEXT_PUBLIC_SITE_URL` 漏写协议头（填 `coderesin.site` 而非 `https://coderesin.site`）→ `new URL()` 抛
  `ERR_INVALID_URL` → 构建在 "Collecting page data" 阶段直接终止（所以只花二十几秒）。
  报错里的 `input:` 字段会原样打印环境变量的值，一眼定位。
- **本地复现手法（不用等远端）**：`NEXT_PUBLIC_SITE_URL="coderesin.site" node node_modules/next/dist/bin/next build`
  → 复现同一个 `TypeError: Invalid URL`。Next 不会用 .env 覆盖已存在的进程环境变量，内联赋值优先级最高。
- **修法（改代码而非只改配置）**：`src/lib/shared.ts` 新增 `resolveSiteUrl()`：trim → 缺协议自动补 `https://`
  → `try/catch` 解析失败回退默认值 → 全程 `console.warn` 打出收到的原值（下次构建日志可直接看到填错的变量）。
  同类的 `NEXT_PUBLIC_SITE_LAUNCH_AT` 也加了 `resolveLaunchAt()`，避免 Invalid Date 让计时器显示 NaN。
- 验证：坏值构建 exit 0 且有警告 / 正常值构建 exit 0 无警告 / lint、类型全绿。commit `730b3fa` 已推送 main。
- **教训**：任何来自环境变量的值，只要会在构建期被求值（`new URL` / `new Date` / `JSON.parse`），
  就必须在代码里归一化 —— 否则「运维填错一个字符串」直接等于「构建失败」。
- 附带发现：`.env` 被提交进了仓库，但内容只是注释模板（所有值留空），**没有真实密钥**，`.env.local` 已 gitignore，无需处理。

## 顶栏窄屏「没有下拉菜单」（本轮修复）
- **现象**：窄屏下首页顶栏只有 `resin-notes` + 搜索 + 一个箭头，点开箭头是**空面板**，三个分类去哪了。
- **根因**：上一轮为消侧边栏重复给 navLinks 加了 `on: "nav"`。这个字段是 **navItems / menuItems 的分流开关**，
  不只是「顶栏 vs 侧边栏」：
  - 首页 Header（`@fumadocs/base-ui/dist/layouts/home/slots/header.js`）里，桌面横向列表是
    `<ul className="flex … max-sm:hidden">`，**窗口 <640px 整个列表被隐藏**；
  - 窄屏唯一入口是右上角箭头展开的 `CollapsibleContent`，而它渲染的是 **menuItems**（不是 navItems）；
  - 分类写了 `on:'nav'` → 不进 menuItems → 窄屏下拉天然是空的。
  - （附：docs 布局压根不渲染 navItems，只渲染 menuItems —— 所以 'nav' 在文档页等于「哪儿都没有」。）
- **修法（不再用 on 字段消重复）**：
  1. `src/lib/layout.shared.tsx` 的 navLinks **去掉 `on`**，恢复默认 `'all'`（顶栏 + 窄屏下拉都有）；
  2. 同文件 `baseOptions()` 增加 `includeNavLinks?: boolean`，`false` 时 `links: []`；
  3. `src/app/docs/layout.tsx` 传 `baseOptions({ includeNavLinks: false })` —— 文档页侧边栏本来就靠页面树列这几个分类，
     不传这批链接就没有重复，且 GitHub 图标不受影响（它由 `githubUrl` 自动追加）。
- **验证（生产模式 CDP）**：390px 首页点箭头 → `aria-expanded` false→true、`#nd-nav` innerText = `resin-notes / 感触 / 工程化 / 技术栈`，截图可见三项 + GitHub + 主题切换；
  docs 1440 侧边栏链接仍是 5 项（`/`、`/docs`、三个分类）+ GitHub，无重复；`next build` exit 0。
- **教训一**：fumadocs 里想「消重复」不要动 `on`，那会连带砍掉窄屏下拉的入口；应该在**布局层**决定传不传这批 links。
- **教训二**：本轮 headless Chrome 连**主题切换都点不动**（`<html>` class 不变），是 hydration 没跑，
  **不能据此判定代码有问题**。可靠姿势：`next build` → `next start -p 3100`（不要占用用户的 3000）→ CDP 点击验证。
  想确认 dev server 是否已加载新代码，可直接 `fetch('http://127.0.0.1:3000/')` 数 HTML 里 `href="/docs/feelings"` 出现次数（改前 1 次、改后 2 次）。
- 探测用的临时 `.probe-*.json` 已全部删除，工作区无残留。
